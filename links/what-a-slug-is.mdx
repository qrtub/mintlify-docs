The slug is the part of a Link's address that identifies it: the `bepjov` in `qrtub.com/bepjov`,
the `exc203` in `qrtub.com/exc203`. Everything else in the URL is fixed. When QRtub asks how you
want a Link created, it is really asking how you want its slug chosen.

## One address shape, whichever type you pick

| Link type | Address shape | Example |
|-----------|---------------|---------|
| Random | `qrtub.com/{slug}` | `qrtub.com/bepjov` |
| Numbered | `qrtub.com/{slug}` | `qrtub.com/exc203` |
| Custom | `qrtub.com/{slug}` | `qrtub.com/boardroom` |

All three sit at the root. There is no prefix on any of them, so an address is always the domain
and the slug — nothing to remember, nothing to leave off when you write one down.

The domain is always lowercase `qrtub.com`. When you print a Link as readable text under a QR code,
print the whole address rather than the slug alone — `qrtub.com/bepjov`, not `bepjov`.

## Case never matters

`qrtub.com/BEPJOV`, `qrtub.com/bepjov` and `qrtub.com/BepJov` all resolve to the same Link. That is
true of all three types.

So how a code is printed is a typography decision rather than a correctness one. Capitals often
read better on a plate at distance; lowercase reads better in a line of body text. Pick whichever
suits the tag — and if crews type addresses by hand on a muddy site with a cracked screen, nobody
gets caught out by a capital.

QRtub displays addresses in lowercase in the app and in exports, except for numbered slugs, which
keep whatever case you claimed the pattern in — so a pattern claimed as `CRA####` prints as
`CRA0042TL`.

## Slugs are unique across all of QRtub, not just your team

Slugs are checked against every Link in QRtub, not just your team's. If another team already holds
`boardroom`, you cannot have it, and QRtub tells you it is in use rather than quietly giving you
something else. The check ignores case, so `Boardroom` is not available either.

Random slugs mostly sit outside that contest. They are letters only and numbered slugs always
contain digits, so those two shapes cannot meet, and a random name is derived through a cipher
rather than drawn and checked, so two random Links can never land on the same slug. A custom slug
*can* take a random-looking name — `bepjov` is legal — and if one has, QRtub simply mints a
different random name instead. That happens silently; there is nothing to resolve.

A slug is fixed once the Link exists. There is no rename: the point of the whole system is that a
printed code keeps resolving, and renaming a slug would break every code already in the field. If
you need a different address, create a new Link and, if the old one is no longer wanted, delete it.

## What varies by type

Each type has its own rules about what characters a slug may contain and how long it can be — a
random slug is always six lowercase letters, a custom slug is validated against a fixed charset and
a reserved-word list, and a numbered slug is built from a prefix, a zero-padded number and a
suffix. Those rules live with each type rather than here.
