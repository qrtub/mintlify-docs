By default a Page is public: anyone who scans the code sees it, no sign-in, no account. Making it
private changes that — the page is only viewable by a signed-in member of the team that owns the
Collection.

Private pages are part of the Scale plan, and there are two places to set them:

- **For a whole Collection** — in the Collection's settings, open the **Scan behaviour** tab, turn
  on **Private pages** under **Who can see these pages**, and press **Save changes**. This sets the
  default for every Item in the Collection.
- **For one Item** — open the Item, go to its **Destination** tab, choose **Page**, and tick
  **Private Page** beneath it. The line under the checkbox says whether the Item is following the
  Collection's default or overriding it.

On other plans both controls carry a **Scale** badge, and switching one on does not make anything
private: the team owner is offered an upgrade, and anyone else is told to ask the owner.

## What a visitor actually sees

When a private Item is scanned:

1. **Nobody signed in** — the visitor is sent to the QRtub sign-in screen, with a return path back
   to the scanned code. After signing in successfully, they land on the page.
2. **Signed in, but not a member of the owning team** — they get a plain not-found page. They are
   not told the Item exists, who owns it, or that they lack permission. There is no request-access
   flow.
3. **Signed-in team member** — the page renders normally.

So a private code is not a soft nudge; to an outsider it is indistinguishable from a code that
points nowhere. That is intentional, but it means a private Item is a poor choice for anything a
customer or subcontractor is meant to reach.

## It gates the redirect too, not just the page

The privacy check runs *before* the Destination is resolved. A private Item that is set to Direct
Mode therefore still demands a sign-in first, and only redirects afterwards. Privacy is a gate on
the scan, not a property of the page layout — which is why the Collection's **Private pages** switch
is there whether or not the Collection shows pages.

## What it does not protect

**Private means "who may view this QRtub page", not "who may use the system it links to."**
Once a viewer is on the page, every Destination button behaves normally. If a button opens a
public URL, that URL stays public — the vendor system on the other end does its own
authentication, or doesn't. Making the Item private does not add a password to anything you link
out to.

It also does not hide Item data from the page's own bindings. A private page renders the same
fields a public one would; the difference is only who is allowed to load it.

If your goal is to keep one button away from the public rather than the whole page, use a
condition on that section instead — a section can be shown only to people signed in to QRtub (any
QRtub account, so it tidies a page rather than protecting it). See
[AdminToolbar](/pages/admin-toolbar), which does exactly that by default, and [Conditional
Visibility](/destinations/conditional-visibility).

## Effect on search engines and link previews

Private pages are given deliberately minimal metadata: the title reads "Private Item", the
description "Sign in to view this item", and search engines are told not to index the page and not
to follow its links. Nothing about the real Item leaks into a search result or a chat-app link
preview. Public pages get the Item's own name, description and image instead — see [Page Metadata
& Social Previews](/pages/page-metadata).

## The Collection default and Item exceptions

The Collection setting is a default, not a lock. Items that have not been set differently follow
it, so switching **Private pages** on makes all of them sign-in-only at once, and switching it off
makes them public again. An Item set differently keeps its own setting either way — a public Item
can sit in a private Collection, and a private Item in a public one.

One catch when adding Items to a private Collection: the new-Item form starts with **Private
Page** unticked, and saving it that way makes the new Item public — including an Item set to
**Destination**, where the checkbox is not shown. For a new Item that should be private, tick
**Private Page** before you save; the line under it then reads "Following this collection's default
(private)."

There is no bulk action for changing privacy on a selection of Items; between the Collection
default and the per-Item checkbox, those are the two controls.
