QRtub manages the QR-code layer between your physical items and the software systems that
serve them. A QR code encodes a QRtub Link instead of a vendor's URL, so you can change
where that code goes — or what it opens — without reprinting anything.

## Nothing here has to be built in order

A Collection, an Item, a Link and a Page do not require each other to exist. You can create
Links and send them to a printer before you know what they will point at, build a Page before
any code opens it, or import real equipment data and print a box of spares in the same
afternoon. Most systems make you finish the database before you can print; QRtub doesn't, and
that changes how you sequence a rollout.

The tutorial below is one workable path through that, not the required one.
