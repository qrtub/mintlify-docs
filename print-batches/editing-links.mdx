A Draft batch's contents are not fixed. You can add links to it or take links out, one at a time
or in bulk, right up until the batch leaves Draft. Every change regenerates the batch's stored
CSV so the file always matches the list.

The rule behind both routes below is the same: **links can only be edited on a Draft batch.**

## From inside the batch

Open the batch and choose **Edit included links**. The dialog has two tabs:

**Current** lists every link in the batch. Filter by link URL, item name or Item ID, tick the
links you want gone (or **Select all filtered**), and choose **Remove** — the button counts what
you ticked, for example **Remove 12 links**.

**Add** searches your team's links by link URL, destination, item name or Item ID. Links already
in the batch are excluded from the results, so everything you see is genuinely addable. The list
shows the first 50 matches with a note like "Showing 50 of 320 available links" — refine the
search to reach the rest, or use **Select all (320)** and QRtub adds every match server-side
without you paging through them.

## From the Items or Links grid

Both grids offer **Add to batch...** in the row menu. In the bulk-actions menu it is **Add to
batch...** on the Links page and **Add selected to batch...** on an Items grid. Picking it opens a
batch picker that lists **only Draft batches** — a batch past Draft is not offered at all, which
is the first place most people notice the rule. On the Links page the row menu also has **Remove
from batch...**, which offers only the Draft batches that link is in.

If the grid is already filtered to one batch, that batch is never offered in the picker (every row
is already in it). When that batch is a Draft, the menus act on it directly instead: **Add to
batch...** adds to it without a picker, an Items grid's bulk menu offers **Add to current batch**,
and **Remove from active batch** takes rows out (in an Items grid's row menu, and in the Links
page's bulk menu).

From an Items grid the selection is Items, and QRtub adds every Link assigned to each Item. Adding
a single Item that has no Link shows the warning "Item has no links to add"; in a bulk add, Items
without a Link are skipped rather than failing the whole operation.

Bulk actions work from the rows you ticked, or from every matching row across pages when you tick
the header checkbox.

## The Draft-only rule, and how it surfaces

Once a batch reaches In Production, Ready or Installed, its link list is frozen:

- **Edit included links** disappears from the batch panel.
- The batch stops appearing in the "Add to batch" picker.
- Where a grid is filtered to that batch, the Links page's **Remove from active batch** is
  disabled, with a tooltip saying the batch's links are locked, and an Items grid stops offering
  **Add to current batch** and **Remove from active batch**.
- An attempt that reaches the server anyway is refused with "Links can only be edited on a draft
  batch."

To change an In Production or Ready batch, revert it to Draft first. Installed cannot be reverted
at all — see [Batch Status: Draft to Installed](/print-batches/batch-status).

## Details worth knowing

- **Adding the same link twice is harmless.** A link already in the batch is skipped, never
  duplicated, so the batch's link count only grows by genuinely new links.
- **The CSV is rebuilt from current data** after every add or remove, so a renamed Item shows its
  new name in the regenerated file.
- **Removing a link from a batch does not delete it.** The Link, its Item and its destination are
  untouched; only its membership in this run goes away.
- **Link and item counts are recalculated** after every change, so the batch row stays accurate.
