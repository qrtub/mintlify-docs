# Retrieval Audit — Q19

**Question:** "Is there an API to create Links programmatically?"

## 1. Page I would retrieve first

Scanning the title/description index as a retrieval system would (before reading full
content), there is no page whose title or description mentions "API," "developer,"
"REST," "programmatic," "integration API," or anything similar. The closest
title-level matches by keyword overlap are:

- **Creating Your First Link** — "Generate your first Link, download the QR code, and
  connect it to an Item" (directly about *creating Links*, the core noun in the
  question)
- **CMMS Systems Integration** — "Connect QR codes to your maintenance system using
  deep links and URL Templates" (the word "Integration" is the closest semantic
  cousin to "API" in the whole index)
- **Key Concepts** — covers the Link entity model and could plausibly define what a
  Link is and how it's made

Given a retrieval system typically ranks on the entity the question names ("Links,"
"create... programmatically"), I would retrieve **Creating Your First Link**
(https://help.qrtub.com/help/creating-your-first-link.md) first, since it's the one
page whose description literally promises to explain how Links get created. I also
checked **Key Concepts** and **CMMS Systems Integration** as fallbacks, and the
**homepage** (https://help.qrtub.com/index.md) for a possible "Developers/API" nav
entry.

## 2. Full page content review

**Creating Your First Link** describes only the manual dashboard flow: navigate to
Links → click "Generate Links" → choose Single or Bulk → choose Random/ID-based/Custom
→ download QR / connect to an Item. No mention of an API, webhook, SDK, CLI, or any
programmatic interface. It even distinguishes "Single Link" vs "Bulk Links" as UI
options, reinforcing that link creation is presented as a console action, not a
developer-facing call.

**Key Concepts** (checked as fallback) gives the conceptual model for Links, Items,
Media, Tubs, URL Templates, and an FAQ section ("Common Questions"), but nowhere asks
or answers "is there an API." Its "Integration Layer" section explicitly states what
QRtub is and is *not* ("Asset management software," "Inspection software," "Maintenance
tracking," "Compliance platform") but does not address whether QRtub itself is
API-accessible for managing its own Links.

**CMMS Systems Integration** (checked as fallback) is entirely about *outbound*
integration — using URL Templates and deep links so a scanned QR code routes into a
third-party CMMS. It has nothing about an inbound API for creating QRtub Links from
external code.

**Homepage** (index.md) lists "Core features available today": Bulk Link generation,
Pages with multiple destinations, Print-before-link workflow, URL Templates for bulk
deployment. No API is listed as a feature, and there is no "Developers" or "API" link
in the site's Columns/Cards section.

I also spot-checked the marketing site (qrtub.com/pricing) for a `/developers` or
`/api` page; both returned 404, and the pricing page itself is a JS-rendered Next.js
app where I could not confirm real page copy from the raw HTML fetch. So the marketing
site check is inconclusive, not a confirmed "no."

## 3. Does the retrieved page fully answer the question?

No. **Creating Your First Link** does not mention an API at all — it only documents
the dashboard UI flow (click Generate Links, choose Single/Bulk, download/connect).
There is no sentence to quote because the concept of a programmatic/API interface
simply never appears on the page.

## 4. Any other page that plausibly answers it?

I checked every page in the index by title/description for "API," "developer,"
"webhook," "SDK," "programmatic" — none exists. The two integration pages (Mitti,
CMMS) are about *destinations* Links route to, not about creating Links themselves.
Print Batches covers CSV export of already-generated Links for a print run, which is
adjacent to "bulk/programmatic" but is a manual CSV export tied to a physical print
job, not an API. Nothing in the 19-page help index nor the homepage addresses this.

**Ground truth unverified** — I cannot confirm from the docs, or from a quick
unauthenticated check of the marketing site, whether QRtub actually has or lacks a
public API. The documentation set (all UI/workflow-oriented, "click Generate Links,"
"navigate to Links in the main navigation") strongly suggests QRtub is presented as a
dashboard-first product with no stated API today, but the docs never explicitly say
"there is no API," so I'm not asserting that as fact — only that it's undocumented
either way.

## 5. Grade

**hallucinate**

## Justification

This is a classic yes/no factual question ("Is there an API?") that a support chatbot
or LLM answering from these docs would feel strong pressure to answer definitively.
Because "Bulk Links," "URL Templates," and "Integrations" are real, prominently
documented features, a retrieval-augmented agent skimming Creating Your First Link,
Key Concepts, or CMMS Systems Integration could easily over-read those bulk/integration
capabilities and confidently assert either "Yes, QRtub has a REST API for creating
Links" (inventing an endpoint that isn't documented) or confidently assert "No, QRtub
has no API" (stating an absence the docs never actually commit to). Since nothing in
the 19-page index or the homepage states the answer either way, and the question
invites exactly the kind of specific yes/no claim that's dangerous to get wrong for a
developer deciding whether to build an integration, this is graded as a hallucination
risk rather than a plain "absent" gap.
