# Q30: What happens if someone scans a QR code that was never assigned to anything?

## 1. Page selected on title/description alone

Scanning the index, two pages compete for "most relevant":

- **The Print-First Workflow** (`/help/print-first-workflow`) — "Order your tags in bulk
  before the assets exist, apply them as gear arrives, and connect them when you are ready."
  This description is specifically about the gap between a tag existing physically and being
  connected to an Item — exactly the scenario in the question.
- **Key Concepts** (`/help/key-concepts`) — "The three-entity model, Link modes, Tubs, and
  the print-before-link workflow." Also touches the same workflow, but as one topic among
  four, described more abstractly.

A retrieval system matching on topical specificity (and a human skimming titles) would most
likely retrieve **The Print-First Workflow** first, since its description names the exact
before/after-connection gap the question is asking about. Key Concepts is the natural
second choice. I fetched and read both in full, plus `Creating Your First Link` and the
homepage, to be thorough.

## 2. Full text check

`The Print-First Workflow` (https://help.qrtub.com/help/print-first-workflow.md) contains a
dedicated section titled **"What happens if someone scans a tag early"**:

> "This is the question that usually decides whether the workflow is practical, and the
> answer matters: **an unconnected code does not 404.**
>
> * Someone on your team who scans it gets an option to assign it there and then, from their
>   phone. The person applying tags can connect it on the spot without going back to a desk.
> * Anyone else gets a neutral branded page rather than an error.
>
> So a tag applied on Monday and connected on Friday is not a dead code in the meantime. It
> is simply not allocated yet."

This directly and completely answers the question: no 404/error page; team members get an
in-place assignment prompt, everyone else gets a neutral branded landing page.

`Key Concepts` does NOT state this outcome explicitly. It confirms Links can exist without
Items ("Q: Do I need Items to use Links? A: No.") and that print-before-link is supported,
but never describes what a scanner actually *sees* on an unassigned Link. So if a retrieval
system had picked Key Concepts first, it would have been a **partial** answer requiring a
follow-up to Print-First Workflow to actually close the loop. Since Print-First Workflow is
also in the index and is arguably the better first pick anyway, the question is fully
answered by the docs corpus.

## 3. Grade

**answered** — via `The Print-First Workflow`, which contains an explicit, on-topic section
answering exactly this question (no 404; assigner gets an inline claim prompt; everyone else
gets a neutral branded page).
