# Q15: Can a QR code send iPhone users to one place and Android users to another?

## 2. Fetched and read in full

`curl -s https://help.qrtub.com/help/device-detection.md` — full page retrieved (see tool output). Confirmed it is a substantial, self-contained page covering device fields, OS fields, browser fields, worked examples, and setup steps.

## 3. Does it answer the question completely, without needing another page?

Yes — completely, with no need to follow a link. The page states plainly, under "Operating System":

> **Field:** `device.os`
>
> **Values:**
> * `'ios'` - iPhone or iPad
> * `'android'` - Android device
> ...
> **Convenience flags:**
> * `device.isIOS` - True if iPhone/iPad
> * `device.isAndroid` - True if Android

And gives a worked example that is literally this exact use case, under "2. Platform-Specific App Downloads":

> **Setup:**
> * Create "Download on App Store" Destination
>   * URL: `https://apps.apple.com/app/yourapp`
>   * Condition: `device.isIOS`
> * Create "Get it on Google Play" Destination
>   * URL: `https://play.google.com/store/apps/details?id=com.yourapp`
>   * Condition: `device.isAndroid`
>
> **Result:** iPhone users see App Store link. Android users see Google Play link.

Plus the general framing sentence at the top:

> QRtub automatically detects what device someone is using when they scan your QR code. You can use this information to show device-specific Destinations or route users to apps that work best on their platform.
>
> One QR code can serve the right experience for everyone.

This directly confirms: yes, a single QR code (via a Page with two Destinations, one conditioned on `device.isIOS` and one on `device.isAndroid`) can send iPhone users to one URL and Android users to another. The "How to Set Up Device Routing" section and "Testing Your Setup" section round out actionable steps (create Destinations, add conditions, test on both device types).

No follow-up page is required to answer the yes/no question or to know how to do it.
