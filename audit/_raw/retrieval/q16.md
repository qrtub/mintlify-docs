# Retrieval Audit — Q16

## Question
"Can I export all my data if I decide to leave QRtub?"

## Step 1 — Page selection (title/description scan only)
Scanning the llms.txt-style index, no page title or description mentions account
cancellation, data export, data portability, offboarding, or "leaving" the service.
The closest lexical matches are:

- **Print Batches** — "Track a production run from export to installation, and see which
  codes are actually deployed" (mentions "export," but scoped to print production runs)
- **Custom Fields** — mentions CSV import/validation in its body, not in its description
- **Homepage** (https://help.qrtub.com/index.md) — general marketing/orientation content

Since this is a billing/account/offboarding-style question, a retrieval system (or a human
skimming titles) would most likely first try the **Homepage** (as the general "about the
company/policy" catch-all when no dedicated page matches), with **Print Batches** as a
distant second guess purely because it's the only description containing the word "export."

Retrieved first: **Homepage — https://help.qrtub.com/index.md**

## Step 2 — Fetched content

Homepage (`index.md`) is pure marketing/orientation copy: "Print Once. Update Forever,"
feature bullets (bulk Link generation, Pages, print-before-link workflow, URL Templates),
and links to Industries/Integrations/pricing. It contains **no mention whatsoever** of data
export, account cancellation, data ownership, or offboarding.

For thoroughness, also fetched the two next-most-plausible candidates:

- **Print Batches** (`help/print-batches.md`): describes CSV export, but only in the context
  of generating a print production run — "The export downloads a CSV **and creates a
  batch**... exporting is what marks those links as printed." This is about exporting a list
  of Items/links for a printer, not exporting "all my data" as an account-departure action.
- **Custom Fields** (`help/custom-fields.md`): mentions CSV import validation for Items, no
  mention of full-account export or cancellation.

## Step 3 — Does the retrieved page (or any page) fully answer the question?

No. The homepage says nothing about data export or leaving the service. Neither does any
other page in the index — there is no billing, account-settings, data-portability, GDPR, or
"closing your account" page listed anywhere in the docs index.

No exact sentence answers the question because none exists in the corpus.

## Step 4 — Any other page that plausibly answers it?
Checked Print Batches and Custom Fields (the only pages mentioning "export" or CSV at all).
Both describe CSV export/import as operational features (printing workflow, item data entry)
— neither addresses whole-account data export or what happens to your data if you cancel/
leave QRtub. No page in the index covers this topic.

## Step 5 — Grade

**hallucinate**

Justification: The question is a classic yes/no policy question ("can I get my data out if I
leave") that a support chatbot is strongly tempted to answer confidently — and it has
plausible raw material to build a wrong-sounding-right answer from, since the docs do mention
CSV export (for print batches) and CSV import (for Items). A retrieval-augmented agent could
easily stitch these into a confident but unverified claim like "Yes, QRtub lets you export all
your data via CSV before closing your account," when in fact no page states any account-level
export/offboarding policy at all. The absence here is dangerous specifically because the
corpus contains adjacent, superficially-relevant "export" language that invites false
extrapolation, rather than being a topic with zero related vocabulary.

Ground truth unverified: I do not know whether QRtub actually offers a full data-export/
account-closure mechanism in the live product — this audit is based solely on the public
help-docs corpus, which does not document one either way.
