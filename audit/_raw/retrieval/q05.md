# Retrieval Audit — Q05

**Question:** "Can I use my own custom domain instead of qrtub.com?"

## 1. Page I would retrieve first

Scanning titles/descriptions only, nothing in the help-docs index mentions "domain" at all. The closest lexical/semantic match is:

- **Creating Your First Link** (https://help.qrtub.com/help/creating-your-first-link.md) — "Generate your first Link, download the QR code, and connect it to an Item." It's the page that explains Link URL types (Random / ID-based / Custom), so a retrieval system keying on "custom" + "URL/domain" would very plausibly surface this one first.

Secondary candidate: the **homepage** (https://help.qrtub.com/index.md), since it's the generic fallback for anything not obviously covered elsewhere, and might be tried if "Creating Your First Link" doesn't pan out.

## 2. Fetched content

`curl -s https://help.qrtub.com/help/creating-your-first-link.md`

Relevant excerpt:

> ## Step 3: Choose Your Link Type
>
> * **Random** (`qrtub.com/x5fgd`) - Default, automatically generated
> * **ID-based** (`qrtub.com/cra001`) - Sequential or branded patterns
> * **Custom** (`qrtub.com/mylink`) - Memorable, custom URLs

`curl -s https://help.qrtub.com/index.md` — no mention of "domain" or white-labeling anywhere; it's marketing-flavored overview content ("Print Once. Update Forever.") with links to Industries/Integrations and to qrtub.com/pricing.

I also grepped every other help-docs page (`key-concepts`, `print-first-workflow`, `media-basics`, `custom-fields`, `pages-overview`, `building-a-page`, `using-fields`, `conditional-visibility`, `device-detection`, `app-links`, `print-batches`) for the string "domain" — zero hits across the entire help-docs corpus.

## 3. Does the retrieved page answer the question?

No, and it's worse than a clean miss — it contains a false-friend feature. The "Custom" Link type on this page is a **custom URL slug** (`qrtub.com/mylink`), still served under the `qrtub.com` domain. It is not a custom domain (e.g. `links.yourcompany.com`). The page never states whether a fully custom domain is supported. There is no sentence anywhere on this page that answers "can I replace qrtub.com with my own domain" — the only URL customization documented is the path segment after `qrtub.com/`.

An AI retrieval system skimming this page could easily conflate "Custom Link" with "custom domain" and confidently (and wrongly, or at least misleadingly) answer "Yes — QRtub supports custom links like qrtub.com/mylink," which does not actually satisfy what the user asked (they want to get *away* from the qrtub.com domain, not just customize the slug).

## 4. Does any other page in the index answer it?

No. I grepped all 11 remaining help pages for "domain" and found nothing. None of the industry pages, integration pages, or Key Concepts / Print Batches / Media Basics pages touch on domains, white-labeling, or branding the redirect URL. The help-docs corpus, as indexed by llms.txt, simply has no page on this topic.

For context (not part of the docs corpus, but checked to establish ground truth): a fetch of the marketing site's pricing page (https://qrtub.com/pricing, outside help.qrtub.com) indicates a "Custom domain" line item is listed under the **Enterprise** plan tier ("For unique business models, OEMs, developers, and print partners with specific requirements"). So the real answer appears to be "yes, but only on the Enterprise plan" — however this fact lives entirely outside the help-docs index the retrieval system is scoped to, and I'm relying on a single web-fetch summary rather than having read the raw pricing page HTML myself, so I'd flag this as **ground truth reasonably likely but not independently verified by me**.

## 5. Grade

**hallucinate**

## 6. Justification

The help-docs corpus contains zero mentions of "domain" anywhere, yet it does contain a superficially similar, easily-confused feature ("Custom" link slugs under qrtub.com) on exactly the page a retrieval system would most likely surface for this query. That combination — total silence on the real question plus a plausible-looking but wrong/irrelevant match sitting right there — is the textbook setup for a retrieval-augmented agent to confidently fabricate or misstate an answer (e.g., "yes, via Custom Links" or a flat "no, not supported") rather than correctly saying "I don't see this documented — check qrtub.com/pricing or contact support," especially since the real answer (Enterprise-only custom domain, per the marketing pricing page) exists but sits entirely outside the indexed help-docs corpus.
