# Retrieval Audit — Q21

## Question
"Is there a maximum number of Destinations I can put on one Page?"

## Step 1: Page selected from index alone
Based only on titles/descriptions, the best candidate is **Pages Overview**
(https://help.qrtub.com/help/pages-overview.md) — its description is "What a Page is, when a
Link should open one, and how Destinations fit together," which explicitly names both "Page"
and "Destinations," the two entities in the question. **Building a Page** (which covers the
actual Page Editor UI where Destinations/ActionLink sections are added) is a strong second
candidate and was also fetched.

## Step 2: Fetched and read in full
- `https://help.qrtub.com/help/pages-overview.md`
- `https://help.qrtub.com/help/building-a-page.md`
- (Also checked `key-concepts.md` and `conditional-visibility.md` as secondary candidates, since
  both discuss Destinations extensively.)

## Step 3: Does the retrieved page answer the question completely?

**Pages Overview** describes what a Page is, Page Mode vs Direct Mode, key benefits, and how to
create a Page (turn on the page option for a Tub, create an Item, assign a Link, "Add
Destinations to route people to the systems they need"). Nowhere does it state a cap, limit, or
maximum count on Destinations. No sentence addresses the question at all.

**Building a Page** covers the Page Editor in detail — 17 available section types, how to add
and arrange them, binding data, conditional visibility, theming, and the override/save model.
Destinations are represented via the **ActionLink** section, and the page explains what happens
when a single ActionLink's URL can't resolve, but it never says how many ActionLink/Destination
sections a Page can contain, nor mentions any per-page cap on sections in general.

**Key Concepts** and **Conditional Visibility** both discuss Destinations at length (multiple
Destinations per Page is core to the product's value proposition — "One Code, Every System") but
neither states a numeric or practical maximum either.

**Verdict:** No page in the index states a maximum number of Destinations per Page — not even
indirectly (e.g., no "we recommend keeping it under N for UX reasons" or "Enterprise plans allow
more Destinations" note tying it to plan limits).

## Step 4: Any other page that might answer it?
Checked all four most plausible pages (Pages Overview, Building a Page, Key Concepts,
Conditional Visibility). None contains the answer. No other page in the index is topically
closer. The marketing site (qrtub.com/pricing) might plausibly gate this by plan tier, but that
is outside the docs index and not confirmed to exist.

## Grade: hallucinate

## Ground truth
Ground truth unverified — I cannot confirm from the docs whether QRtub enforces a technical
maximum (e.g., a hard limit) or leaves it unbounded (subject only to plan/UI practicality). The
docs are silent either way.

## One-line justification
The question asks for a specific factual limit (a number or a firm "no limit"), several
pages discuss Destinations/Pages at length without ever stating one, and this combination
of confident-sounding adjacent context plus total silence on the actual limit is exactly the
setup where a retrieval-backed agent is likely to fabricate a plausible number (e.g., "up to
10 Destinations") rather than say it doesn't know.
