# Q10 Retrieval Audit

## Question
"Can I print QR codes before the physical equipment even exists?"

## Step 1: Page selection from titles/descriptions alone
Scanning the index, one page's title and description are an almost verbatim match for the
question: **The Print-First Workflow**
(https://help.qrtub.com/help/print-first-workflow.md) —
"Order your tags in bulk before the assets exist, apply them as gear arrives, and connect
them when you are ready."

Other pages that mention printing (Physical Media Management Basics, Print Batches, Creating
Your First Link, Key Concepts) are plausible secondary candidates, but none of their
descriptions name the "before the asset exists" scenario the way this one does. This is the
clear first retrieval choice a keyword- or embedding-based retriever, or a human skimming
titles, would make.

## Step 2: Fetched page
`curl -s https://help.qrtub.com/help/print-first-workflow.md`

Full content read (reproduced/quoted below).

## Step 3: Does it fully answer the question, without following another link?
Yes. The page is built entirely around this exact scenario and answers it directly, with no
need to chase a link elsewhere. Key quotes:

> "The print-first workflow inverts it: the codes exist before the records do."

> "**1. Generate the Links first.** Create as many as you need — a hundred, a thousand —
> before any Items exist. Each one is a real, resolvable URL from the moment it is created."

> "**2. Send the batch to be produced.** Export the list and give it to whoever makes your
> tags. Plates, engraved labels, weatherproof vinyl, NFC inlays — the medium does not matter,
> because all it has to carry is a URL."

> "**3. Apply tags as gear arrives.** Fix a tag to each asset as it lands, in whatever order
> things turn up. No decisions required beyond 'this tag is now on this machine'."

It also proactively answers the natural follow-up ("what happens if someone scans one of
these tags before it's connected to an asset?"), which a user asking this question would
almost certainly want next:

> "This is the question that usually decides whether the workflow is practical, and the
> answer matters: **an unconnected code does not 404.**"

So the page answers not just "yes, you can," but also the practical mechanics (batch
generation, production, application, later connection) and the safety net for scanning an
unconnected tag — all without requiring a hop to another page.

## Step 4: Would any other page also plausibly answer it?
- **Key Concepts** covers the "print-before-link workflow" at a conceptual level and is
  linked from this page, but it's the general/overview version; Print-First Workflow is the
  dedicated, complete treatment.
- **Print Batches** covers tracking a bulk production run "from export to installation" and
  is complementary (the export/production logistics side) but doesn't itself state that codes
  can exist before assets do — it assumes that premise rather than establishing it.
- **Creating Your First Link** and **Physical Media Management Basics** are adjacent
  workflow/materials pages but do not address the core question.

None of these is needed, though — Print-First Workflow alone is sufficient and complete.
