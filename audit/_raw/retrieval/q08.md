# Retrieval Audit — Q08

## Question
"What's the difference between a Link and a Page?"

## Step 1: Page chosen from index alone
Scanning only the titles/descriptions in the index, **Key Concepts**
(https://help.qrtub.com/help/key-concepts.md) is the obvious first pick — its description is
literally "The three-entity model, **Link modes**, Tubs, and the print-before-link workflow,"
and it's the page that defines core vocabulary. "Pages Overview" is a very plausible second
choice (description: "What a Page is, when a Link should open one, and how Destinations fit
together") since it also directly names both terms. A retrieval system doing single-page
top-1 retrieval would most likely rank Key Concepts first because it's the terminology/glossary
page and the query is a definitional "what's the difference" question; Pages Overview would be
the natural second hit if the system reads more than one page.

## Step 2: Fetched and read in full
Fetched both:
- https://help.qrtub.com/help/key-concepts.md
- https://help.qrtub.com/help/pages-overview.md

## Step 3: Does Key Concepts alone fully answer the question?

Yes. Key Concepts explicitly defines Link as an entity, then separately defines Page as one of
the two modes a Link can operate in, and gives a direct contrast. Quoted material:

> **Link**
> **What it is:** The QRtub-managed URL that QR codes encode.
> ...
> **Key point:** Links are digital patterns—the URLs that QR codes resolve to. They exist
> independently from Items...

> ## Link Modes
> Links can operate in two modes:
>
> ### Direct Mode
> **How it works:** Immediate redirect to a single Destination.
>
> ### Page Mode
> **How it works:** Link opens a Page—a mobile-friendly landing page where users select from
> multiple Destinations.

And in the "Common Questions" section, directly under Key Concepts:

> **Q: What's the difference between a Link and a QR code?**
> A: A Link is the QRtub-managed URL (`qrtub.com/r/xxxxx`). A QR code is one way to encode
> that Link (the black/white pattern).

(That FAQ answers Link-vs-QR-code, not Link-vs-Page — but the Link Modes section a few
paragraphs earlier does answer Link-vs-Page directly and completely: a Link is the
QRtub-managed URL/address; a Page is the landing-page destination-selector that a Link can be
set to open, as one of its two possible modes, the alternative being a direct single-URL
redirect.)

This is a complete, self-contained answer. No need to follow a link to another page to
understand the conceptual distinction.

## Step 4: Would another page also answer it?

Yes — **Pages Overview** independently and just as directly answers the same question, with an
even crisper side-by-side framing:

> ## Page Mode vs Direct Mode
> | Mode | Behavior | Best For |
> |---|---|---|
> | **Page Mode** | Opens landing page with multiple Destinations | Multi-system integration,
> audience routing |
> | **Direct Mode** | Redirects immediately to single Destination | Simple redirects,
> single-purpose codes |

Combined with its opening description of Page ("a mobile-friendly page with multiple
Destinations"), this page alone would also fully answer the question, reinforcing that this
is a well-covered, unambiguous concept in the docs — not a case where the retrieval system
needs to guess or synthesize across pages.

## Grade: answered

## Justification
Both the top-ranked page (Key Concepts) and a plausible second candidate (Pages Overview)
state the Link/Page distinction explicitly and unambiguously in prose a single page contains
in full, so a retrieval system landing on either page produces a correct, complete answer
without hallucination or inference. Ground truth is directly verifiable from the docs
themselves (not unverified) — this is documented product terminology, consistently used across
both pages.
