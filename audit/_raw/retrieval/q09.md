# Q09 — Retrieval Audit

## Question
"Can I bulk-import my list of equipment instead of adding items one at a time?"

## Step 1 — First page to retrieve (title/description only)
Scanning the index titles/descriptions for something matching "bulk," "import," "equipment list," or "adding items":

- **Creating Your First Link** — "Generate your first Link, download the QR code, and connect it to an Item" — this is the canonical onboarding/"add an item" page, and its title most directly echoes the "adding items one at a time" half of the question. This is the page a title/description-only retrieval pass would most plausibly rank first.
- Key Concepts is a close second (mentions Tubs/Items and print-before-link workflow, and its content elsewhere touches "Bulk Link generation"), but its description doesn't surface "import" or equipment data at all.
- Custom Fields' description ("Define the fields your Items need... link Items to other records") never mentions import/CSV/bulk, so on description alone it would rank low despite (as discovered below) being where the real answer lives.

**First pick: Creating Your First Link** (`https://help.qrtub.com/help/creating-your-first-link.md`)

## Step 2 — Fetched and read in full
Retrieved the full markdown. Content is a 4-step walkthrough: Navigate to Links → Generate a New Link (offers "Single Link" vs "Bulk Links") → Choose Link Type → Print or Connect to an Item.

Relevant excerpt:

> **Single Link** - Generate one Link at a time
> **Bulk Links** - Generate multiple Links for professional printing

## Step 3 — Does this page fully answer the question?
**No.** "Bulk Links" here means generating many blank Link URLs/QR codes for printing — it is not about importing a spreadsheet of existing equipment (names, serial numbers, custom-field data) as Items. The page never mentions CSV, spreadsheet import, or populating Item data in bulk. It only says Items are connected to Links one at a time ("Connect the Link to an Item"). So the literal question — importing an equipment *list* instead of adding *Items* one at a time — is not addressed here at all. No quote from this page answers it.

## Step 4 — Checking other pages in the index
Checked Key Concepts (full three-entity/Tubs explanation, "Bulk Link generation" is listed as a homepage feature but the Key Concepts page itself never mentions importing Item data) and Custom Fields. Custom Fields contains the only real evidence in the whole index that bulk Item import exists:

> "Required fields are enforced when Items are created or edited, **including during CSV import** — a row missing a required value is rejected while the rest of the file still imports."
>
> "Fields with allowed values are also validated on import, so a typo in a status column is caught rather than silently creating a new status."

This confirms QRtub *does* support CSV import of Items, with per-row validation. However:
- This is a single throwaway clause buried in a "Required fields and validation" subsection about field configuration — not a dedicated explanation of the import feature.
- It gives no instructions on where to find the import button, accepted file format/columns, how Tub/custom-field mapping works, whether Links get auto-generated/attached, or any size limits.
- Its page description doesn't mention import at all, so a retrieval system ranking by title/description (per Step 1) would be unlikely to select it first, even though it holds the only confirming fact in the corpus.
- Also checked the homepage (`index.md`, not in llms.txt) — it lists "Bulk Link generation" and "URL Templates for bulk deployment" as core features but never mentions importing Item/equipment data either.

No page in the index provides a complete, dedicated answer (a "yes, here's how" walkthrough) to this question.

## Grade
**partial**

Ground truth: CSV import of Items does appear to be a real, confirmed feature (stated plainly in Custom Fields), so this is not a case of "absent" or "hallucinate" — the fact is documented, just not where a title/description-driven retrieval pass would look first, and not with complete how-to detail. Flagging as ground truth confirmed (not unverified), since the Custom Fields page states it as existing product behavior rather than a hypothetical.

## One-line justification
The page most retrieval systems would fetch first (Creating Your First Link) only covers bulk *Link* generation and never addresses importing equipment/Item data, while the one page that does confirm CSV import of Items (Custom Fields) buries it in an unrelated validation aside with no dedicated how-to — so the question is answerable in principle but not completely from any single retrieved page.
