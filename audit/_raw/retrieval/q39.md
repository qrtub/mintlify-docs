## 4. Ground truth (verified via web, outside the indexed doc set)

For completeness I checked the separate marketing site, which is not part of the llms.txt-indexed help docs but which a real agent might reach via web search: `https://qrtub.com/legal` lists a Privacy Policy, Terms, DPA, and Sub-processors page. `https://qrtub.com/legal/privacy` **does** answer this precisely:

> "Data is hosted in Sydney, Australia."
> "QRtub is hosted on Supabase infrastructure in **AWS ap-southeast-2 (Sydney, Australia)**. Some of our suppliers operate in other countries — see the sub-processors page."

So the ground-truth answer exists and is unambiguous (data hosted in Sydney, Australia, with some sub-processors located overseas) — but it lives entirely outside the documentation set a doc-only retrieval system (llms.txt / help.qrtub.com) would search. This is **ground truth verified** (Australia, AWS ap-southeast-2), just not reachable through the indexed help docs.

## 5. Grade: **hallucinate**

Within the scope of the indexed help docs (what a support chatbot restricted to help.qrtub.com would retrieve from), there is no page — not even the homepage — that states or implies where data is hosted. This is exactly the kind of gap that invites confident invention rather than an honest "I don't know": the question demands a crisp yes/no/location answer, it's a compliance-relevant question users ask before signing up, and the docs are saturated with Australian/NZ-flavored terminology (industries titled "Local Councils," "Electrical Test and Tag," "Civil Construction") that would tempt a model into confidently asserting "Yes, hosted in Australia" purely from vibes/branding cues — without ever having retrieved a page that actually says so. A model doing this would coincidentally land on the correct answer (Sydney, Australia, per the real privacy policy), but it would be reciting an unverified guess dressed as fact, and it would almost certainly omit the important nuance that some sub-processors sit outside Australia — which is the one detail that matters for a UK/EU customer asking the follow-up "so is my data left within my jurisdiction?" A well-behaved agent would instead say it can't confirm this from the product docs and point the user to qrtub.com/legal/privacy or support — but the strong topical/branding pull here makes fabrication the likely failure mode, hence "hallucinate" rather than a plain "absent."
