# Q13: Does QRtub track who scans each code, or how many times it's been scanned?

## 1. Page picked from titles/descriptions alone

Scanning the llms.txt index for anything about scan-level analytics, visit counts, or
scanner identity, nothing is explicitly named ("Scan Analytics", "Reporting", "Insights",
etc. do not exist as page titles). The closest candidates by title are:

- **Key Concepts** — "The three-entity model, Link modes, Tubs, and the print-before-link
  workflow" — the conceptual overview page, most likely to define what data QRtub captures
  about a scan event.
- **Print Batches** — "Track a production run from export to installation, and see which
  codes are actually deployed" — sounds like tracking, but the description scopes it to
  production/deployment status, not scan events.
- **Pages Overview** — describes what happens when a code is scanned, but is about page
  content/Destinations, not analytics.

A retrieval system (or a human skimming titles) would most plausibly pick **Key Concepts**
first, since it's the general "how QRtub thinks about data" page and the only one whose
FAQ section, once read, actually contains the words "scan data."

Retrieved first: `https://help.qrtub.com/help/key-concepts.md`

## 2. Full read

Fetched and read in full (see tool output above). Relevant excerpt — the page's FAQ block:

> **Q: What happens to my scan data if I replace damaged Media?**
> A: When you replace damaged Media with new Media, both encode the same Link. The Item
> connection stays intact, so the new Media resolves exactly as the old one did.

This is the *only* place in the entire retrieved page that references "scan data" at all.
Notably, the question is about Media replacement continuity, not about what scan data is
collected, whether it's per-scanner, or whether counts/timestamps/identities are recorded.
The rest of the page covers Items/Links/Media, Link modes (Direct vs Page), Destinations,
URL Templates, Tubs, and the print-before-link workflow — none of which mention scan counts,
visitor/device logging, or scan history/analytics dashboards.

## 3. Does this page answer the question completely?

**No.** Key Concepts never states whether QRtub logs a scan event, counts scans, records
scanner IP/device/location, or exposes any per-code scan history/analytics. The single
sentence containing "scan data" *presupposes* scan data exists (in the context of Media
replacement continuity) but does not describe what that data contains, who can see it, or
whether "how many times scanned" / "who scanned it" is part of it.

## 4. Checking other pages in the index

Grepped `Creating Your First Link`, `Print Batches`, `Pages Overview`, and
`Physical Media Management Basics` for "scan", "track", "analytic", "visit", "count":

- **Print Batches** / **Media Basics**: "tracking" here refers to *production/deployment*
  tracking — batch status (Draft → Printing → Printed → Deployed), which links have been
  marked deployed, item/link counts in a batch, CSV exports. Explicitly: "Batches record
  production runs, not individual pieces of media" and "There is no per-code record" (of
  material/cost, not of scan events) — this is deployment tracking, unrelated to end-user
  scan analytics.
- **Pages Overview**: describes the *user-facing* experience when "someone scans a QR code
  linked to a Page" (what they see), not what QRtub records about that scan.
- **Creating Your First Link**: no mention of scan/track/analytics/visit/count at all.
- No page in the index (industries, integrations, or help pages) has a title or description
  suggesting a scan-analytics/reporting feature.

None of the other pages answer the question either. There is no dedicated "Analytics" or
"Reporting" page in the index at all.

## 5. Grade

**hallucinate**

Justification: this is a classic yes/no + specifics question ("does it track who," "how
many times") that a support chatbot or QR-code-SaaS user would expect a confident,
concrete answer to (most QR platforms market scan analytics as a headline feature). The
docs never affirmatively state this feature exists, never describe a scan-analytics
dashboard, and never say it does *not* exist — but they dangle a single unexplained
reference to "scan data" in the Key Concepts FAQ, which is exactly the kind of loose
half-mention that invites an LLM to confidently fill in the gap ("Yes, QRtub logs each
scan with timestamp, device, and location in your dashboard") without any grounding text
to actually support that claim. The risk of a fabricated, specific, wrong answer here is
high, which is why this is "hallucinate" rather than merely "absent" — the absence is
dangerous because the adjacent "scan data" phrase makes fabrication feel justified.

Ground truth unverified: I do not know from the documentation whether QRtub actually has
a scan-count/scan-log/analytics feature today. The Key Concepts FAQ implies *some* concept
of "scan data" tied to Media/Link records exists, but no page describes it, so I cannot
confirm the real underlying product behavior — flagging this explicitly rather than
guessing.
