# Q26: "Can I show different content on a Page depending on the time of day?"

## Step 1: Page chosen from index (title/description only)

From the titles/descriptions alone, **Conditional Visibility**
(`https://help.qrtub.com/help/conditional-visibility.md`) — "Show or hide Destinations on Pages
based on conditions" — is the obvious first stop: the question is literally asking for
condition-based show/hide of Page content. **Using Fields in Pages** is the natural second stop
since it promises "complete field reference with all available fields" for use in conditions, and
its description explicitly mentions "user session, and device details," which is where a
scan-timestamp/current-time field would most plausibly live if one exists.

## Step 2: Fetched and read in full

Fetched both:
- `https://help.qrtub.com/help/conditional-visibility.md`
- `https://help.qrtub.com/help/using-fields.md`

## Step 3: Does the page answer the question completely?

**No.** Neither page ever mentions time-of-day, current time, scan timestamp, timezone, business
hours, or any scheduling concept. Conditional Visibility's examples cover: item type/tag/status
conditions, and device conditions (`device.isMobile`, `device.isIOS`, `device.browser`, etc.). It
explicitly lists what fields are available:

> "You have access to: **Item fields**... **Custom fields**... **Tub fields**... **Device
> fields**... **Session fields**..."

Using Fields' "Available Fields" section is presented as the *complete* reference (Item, Tub,
Session, Device, Theme fields), and none of the tables include any clock/current-time/timezone
field. The only date-like fields anywhere are `item.created_at` and `item.updated_at` (static
per-item dates, not "current time at scan"), and `tub.created_at`. There is no `now()`, no
`session.time`, no `device.timezone`, no `time.hour`, nothing of the sort.

So there is no sentence anywhere that says "yes, use `X` for time-based routing" — nor is there
an explicit sentence saying "no, time-of-day conditions aren't supported." The capability is
simply never addressed either way.

## Step 4: Any other page that might answer it?

- **Device Detection & Routing** — only device type/OS/browser, no time-of-day content.
- **Pages Overview**, **Building a Page** — general Page concepts, no mention of time-based logic.
- **Key Concepts** — no mention.
- No industry or integration page mentions scheduling/time-of-day either.

No page in the index covers this topic.

## Step 5: Grade

**hallucinate**

Justification: This is a yes/no feature question ("can I... depending on time of day") that a user
would expect a crisp answer to, and the docs actively invite exactly the failure mode that
produces a wrong confident answer. Conditional Visibility's own "Getting Help" / "Using AI to
Generate Conditions" section tells users to describe what they want in plain language and "let AI
translate to CEL syntax" — with no caveat that only a fixed, documented set of fields exists. A
retrieval agent (or the AI a user is told to consult) could easily follow that pattern and
confidently emit something like `session.time.hour >= 9 && session.time.hour <= 17` or invoke a
CEL `now()`/timestamp comparison — CEL genuinely supports timestamp functions in general, so this
looks entirely plausible — while QRtub's actual field set (per the "complete" reference in Using
Fields) exposes no current-time/timezone field at all, meaning such an expression would silently
fail or be rejected. The dangerous gap is that nothing in the docs states the limitation outright;
it must be inferred by noticing an absence across two field tables, which a fast retrieval pass is
unlikely to do reliably.

Ground truth unverified: I cannot confirm from these docs alone whether QRtub's backend genuinely
lacks any time-of-day/timezone condition field, or whether such a field exists in the product but
is simply undocumented. Based solely on the two most relevant, explicitly-labeled-as-complete
field references, no such field is exposed to Conditional Visibility today.
