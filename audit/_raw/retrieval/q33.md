# Q33: "How do I set up a QR code that opens a PDF or document directly?"

## 1. Page selected for first retrieval (title/description only)

Scanning the index titles/descriptions, the strongest match is:

**Key Concepts** (`https://help.qrtub.com/help/key-concepts.md`)
> "The three-entity model, Link modes, Tubs, and the print-before-link workflow"

The word "directly" in the question maps naturally onto **Link modes** — specifically "Direct Mode" vs "Page Mode" — which is the exact conceptual fork this question is asking about (do I need a landing Page, or can the code just go straight to the file?). A close second candidate by description is **Pages Overview** ("What a Page is, when a Link should open one, and how Destinations fit together"), since it explicitly names "Destinations." Both were fetched; Key Concepts is treated as the primary retrieval, Pages Overview as the secondary check (step 4).

Other titles considered and rejected as primary: "Creating Your First Link" (onboarding steps, no mention of destination/file types), "App Links & Fallback URLs" (this is about native mobile app deep-linking, not opening a PDF — a retrieval system might momentarily consider it but the description clearly says "open mobile apps," not files).

## 2. Full page fetched and read

`curl -s https://help.qrtub.com/help/key-concepts.md` — full content read (also fetched `pages-overview.md` and `creating-your-first-link.md` for comparison).

## 3. Does Key Concepts fully answer the question on its own?

Partially, via synthesis of two separate subsections rather than one direct answer.

Relevant quotes:

- Link Modes → Direct Mode:
  > "**How it works:** Immediate redirect to a single Destination."
  > "**When to use:** Simple redirects (QR code → one URL) ... **Example:** QR code on a poster → Event registration page"

- Destinations → Destination Types:
  > "**Current Destination Types:** \* **External URLs** - Any web address (your systems, documentation, websites)"

- Page Mode example (illustrating that documentation/PDFs are a normal destination content type, though shown here inside a *Page*, not Direct mode):
  > '"Operator Manual" → PDF documentation'

Taken together these establish that yes, a Link can redirect straight to any external URl — including a PDF hosted somewhere — with no intermediate landing page, by using Direct Mode. That answers the "is this possible / what's the mechanism" part of the question.

What it does **not** give: any procedural, UI-level instructions — no "click here, paste the file's URL, set the mode to Direct" steps. The page is conceptual, not a walkthrough. Nor does it clarify whether QRtub itself can host an uploaded PDF, versus requiring the PDF to be hosted externally (the phrase "External URLs" strongly implies the latter — you must host the PDF elsewhere and paste its link — but this is never stated as a discrete instruction, it's an inference from the destination-type label).

## 4. Checking other pages

- **Pages Overview** (`pages-overview.md`) adds the operative procedural detail that's missing from Key Concepts:
  > "| **Direct Mode** | Redirects immediately to single Destination | Simple redirects, single-purpose codes |"
  > "In the Tub's settings, turn on the page option ... Left off, scans pass straight through to a single Destination."
  > "Assigning a Link only attaches the URL — on its own it does not produce a page."

  This confirms Direct Mode is the default/no-Page state and that "assigning a Link" attaches "the URL" as the single destination. But it still never spells out the concrete UI step of *where you type/paste that destination URL* for a Direct-mode Item, nor does it mention file types (PDF, doc, etc.) at all.

- **Creating Your First Link** only goes as far as "Connect the Link to an Item" / "Set up a Page with multiple Destinations" — it doesn't cover setting a single Direct destination URL either.

- No page in the index gives an explicit end-to-end procedure: "create a Link → set Direct Mode → enter the PDF's URL as the Destination." The pieces are scattered across Key Concepts (what Direct Mode + External URL destinations are) and Pages Overview (how Direct vs Page is toggled at the Tub/Item level), but a reader has to stitch these together themselves, and the actual UI click-path for entering a Direct destination URL is never shown in the docs.

## 6. Ground truth

Not unverified in the sense of "does this feature exist" — Direct Mode + External URL destinations are clearly documented as a real, supported mechanism, and a PDF is explicitly used as a "documentation" example destination. What's unverified/unstated is whether QRtub can host an uploaded file itself, or only ever redirects to an externally-hosted URL — the docs imply the latter but never say so as a discrete fact.

## One-line justification

Key Concepts (and, as a fallback, Pages Overview) confirm the *mechanism* — Direct Mode redirects a Link straight to a single External URL destination, and documentation/PDFs are cited as a valid destination type — but neither page gives the concrete step-by-step "how do I actually configure this" procedure the question asks for, so the answer is present in spirit but incomplete in practice.
