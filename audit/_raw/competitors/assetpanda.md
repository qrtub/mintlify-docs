# Competitor doc audit — Asset Panda (assetpanda.com)

Audited: 2026-08-19
Scope: public marketing site (www.assetpanda.com) + public knowledge base (help.assetpanda.com) + docs.assetpanda.com (checked, not public docs — see below)

## Site map / what's actually public docs

- `www.assetpanda.com` — marketing site (Yoast/WordPress + WP Engine).
- `help.assetpanda.com` — "Asset Panda Online Knowledge Center." This is the real support/how-to documentation. Built on **MadCap Flare** (client-side JS redirect stub at `/` and `/index.html`; individual topic pages live at flat URLs like `/Start_Building.html`, `/Consumables_and_Inventory_Management.html`). No sitewide crawlable index was found by curl (root and index.html are both empty redirect shells), so pages were located via web search instead.
- `docs.assetpanda.com` — **not public docs.** Returns HTTP 401 on direct request, `robots.txt` is `Disallow: /` for all agents, and response headers (`x-is-k8s`, session cookie) indicate an authenticated app/API surface, not a help site. Excluded from this audit.
- `/docs`, `/support`, `/knowledge-base`, `/kb` on the main domain all 404 (redirect to a generic 404 page). `/help` resolves to an unrelated blog/case-study post, not a docs index.

## 1. Page granularity

Mixed, and skewed toward **long, multi-topic pages with in-page anchor navigation** rather than small single-topic pages:

- `Start_Building.html` (Getting Started) is short — a 5-step onboarding sequence (~200–300 words) with embedded videos. This one is appropriately granular.
- `Consumables_and_Inventory_Management.html` is long — an estimated 2,500+ words covering five distinct sub-topics (Create Groups and Fields, Create Notifications, Quantity Changes, Data and Use, Reports) on one page, with an in-page "click any link to jump there" table of contents rather than being split into separate pages per sub-topic.
- Integration/setup pages (`Asset_Panda_Integrations.html`, `Azure_Active_Directory_and_SAML_Authentication_Setup.html`) are task-scoped single pages, each with its own troubleshooting section folded in at the bottom rather than housed in a shared troubleshooting index.

**Implication for QRtub:** the long consumables/inventory page is the kind of page that hurts retrieval precision for both search and LLM-based Q&A — a query about "quantity change notifications" has to be matched against a page whose title and surrounding content is about five other things. This is a concrete case-in-point for keeping QRtub's pages single-topic rather than merging related how-tos into one long reference page.

## 2. Pricing / plan quotas

**No public pricing or limits page.** `assetpanda.com/pricing/` exists and is easy to find, but it discloses **zero specific numbers** — no plan names, no prices, no asset/user/storage limits. Copy is entirely lead-gen framed: "Get a personalized quote tailored to your organization's asset management needs," "We'll match you with the right Asset Panda plan and features," with a "Book a demo" CTA and a sales phone number. This is a fully custom/enterprise-quote model with nothing quantifiable published.

**Implication for QRtub:** this is a place QRtub's docs can win outright — if QRtub states specific plan quotas (asset counts, user seats, storage, QR scan limits, etc.) on a findable pricing/limits page, that is a direct, verifiable advantage for both self-service ("will this plan fit us?") and for any LLM asked to compare tools, since Asset Panda's page gives an AI nothing concrete to cite.

## 3. llms.txt / AI-facing artifacts

- `www.assetpanda.com/llms.txt` → **200 OK**, exists. Header shows `last-modified: Sun, 16 Aug 2026`, so it's current/actively regenerated.
- `www.assetpanda.com/llms-full.txt` → 404, does not exist.
- `help.assetpanda.com/llms.txt` → 404, does not exist.
- `docs.assetpanda.com/llms.txt` → 401 (subdomain requires auth entirely; not a public artifact).

**Curation quality: low.** The file's own header says "Generated by Yoast SEO v26.7, this is an llms.txt file, meant for consumption by LLMs" — i.e. it's an **automatic byproduct of the Yoast SEO WordPress plugin**, not a hand-curated artifact. Its content is:
- A flat, undescribed list of ~45 marketing/solution/industry pages (e.g. "Construction," "Mining," "Government," "IT Asset Tracking") under a bare "## Pages" heading — no summaries, no indication of what each page actually contains.
- A "## Resources" section listing 5 recent blog posts (with one-line descriptions).
- A "## Pressroom" section listing 5 press releases (with descriptions).
- One "## Optional" line pointing to the XML sitemap.

Critically, **it contains no link at all to `help.assetpanda.com`** — none of the actual how-to/support documentation is represented in the llms.txt. An LLM or AI answer engine consuming this file would see only marketing/solutions/press content and would have no path into the real product documentation. This is effectively an SEO artifact wearing an AI-facing filename, not a curated knowledge surface.

**Implication for QRtub:** having an llms.txt is table stakes to note, but the bar to actually clear is low — a real, hand-picked llms.txt that links into the genuine help-center content (not just marketing pages) would materially outperform Asset Panda's on any AI-assisted answer or comparison, since Asset Panda's plugin-generated file is actively misleading about where the real documentation lives.

## 4. Other structural observations

- **Left-hand sidebar TOC**, present on knowledge-base pages (per page content: "Use the table of contents located on the left side of this help topic page to view and navigate through our existing integrations"). No breadcrumb trail was found on any page checked.
- **No "last updated" / revision date stamps** were observed on any knowledge-base article fetched (Start_Building, Consumables_and_Inventory_Management, Asset_Panda_Integrations). For a live SaaS product this is a real gap — a reader (or an LLM citing the page) has no way to judge whether steps/screenshots are current.
- **No dedicated glossary page** found (targeted search for glossary/FAQ/troubleshooting on the domain surfaced only per-page troubleshooting subsections, not a standalone index).
- **No dedicated FAQ page** found; troubleshooting content is embedded contextually at the bottom of individual setup/integration articles (e.g., SAML setup page has its own "errors during setup" section) rather than centralized.
- Every knowledge-base page ends with direct human-support contact info (email, phone, live chat) — a consistent fallback CTA that's easy to overlook as a "small" detail but is worth matching if QRtub doesn't already do it consistently on every page.

## Net takeaways plausibly worth acting on for QRtub

1. Avoid long, multi-subtopic pages with anchor-jump TOCs (seen in Asset Panda's inventory/consumables page) — keep pages single-topic; this is a direct retrieval/answer-quality risk, not just a style preference.
2. A real pricing/limits page with specific numbers is an available competitive edge — Asset Panda publishes none.
3. If QRtub builds or maintains an llms.txt, make sure it actually points into the real docs/help content, not just marketing pages — Asset Panda's auto-generated one is a cautionary example of getting this wrong.
4. Consider adding "last updated" stamps to task/how-to pages, since Asset Panda's docs conspicuously lack them and it undermines trust in step-by-step accuracy for an evolving product.
