title: "Importing a Collection Backup"

description: "Restoring a backup file into an existing Collection: what Merge adds, what Replace overwrites, and what Replace keeps — the Items and the link settings"
---

Importing restores a backup file into a Collection that already exists. Open **Settings → Admin →
Backup & restore → Manage backup**, pick an import mode, then **Choose Backup File** and pick the `.json` file. A
confirmation step lists what will happen before anything is written.

There are two modes and they are not variations on a theme — one is additive, the other deletes
data.

## Merge — additive

Merge compares the backup's fields against the Collection's and **adds only the fields that are
missing**. Fields the Collection already has are left exactly as they are: same type, same labels,
same allowed values, same defaults. No field is overwritten and no Item data is touched.

What Merge does *not* leave alone is the page design. **If the backup contains a page template —
and it almost always does — that template replaces the Collection's current one.** The
confirmation step says as much ("Update page template if included"), and it is easy to skim past.
If you only want the fields, export a backup of the current page design first so you can put it
back.

Merge also applies the backup's per-Item page overrides to Items in this Collection with a
matching Item ID (or name), replacing whatever override those Items had.

Collection details — name, description, cover image, Items label — are untouched by Merge, and so
are its other settings.

## Replace — destructive

Replace overwrites the Collection from the backup: details, the entire field schema, the scan
behavior default, the **Private pages** setting, the default destination and the page template.
You have to type `REPLACE` and choose **Replace collection** to confirm it, and it cannot be undone.

It also removes every per-Item page override in the Collection, then restores the ones the backup
carries onto Items with a matching Item ID (or name). An override the backup does not carry is
gone.

Two things Replace keeps:

- **The Items.** A backup QRtub exports never contains Items (see [Exporting a Collection
  Backup](/collections/export-backup)), so the Collection's Items stay, and the result says so: *"This
  backup does not include items, so the N item(s) already in this collection were kept."* Only a
  hand-edited backup that carries an `items` array replaces them; the existing Items are then
  deleted and their Links released to your unassigned pool, so Tags already produced keep working.
- **The link-generation settings.** A numbered pattern is a reservation, so the Collection keeps
  the one it has, and the result notes it when the backup's settings differ.

A backup taken from a Collection with **Private pages** turned on needs the Scale plan to replace
a public Collection; on other plans the import is refused with *"Private scanning is not included
in this plan."*

If what you actually want is "this backup, as a fresh Collection," use [Creating a New Collection
From a Backup](/collections/new-collection-from-backup). It is safe by construction — nothing
existing is involved.

## What both modes tell you afterward

A summary reports what changed: whether the Collection's settings were updated, how many new
fields were added, and whether the page template was replaced. Warnings appear in the same dialog
rather than silently — the ones worth reading are:

- **Items kept** (Replace), with the count, as above.
- **Link settings kept** (Replace): *"This collection kept its own link settings; the backup's were
  not applied."*
- **Overrides that found no matching Item.** Per-Item page overrides are matched by Item ID, or
  name, so an override whose Item does not exist in the target is skipped and named.
- **Skipped rows**, in the rare case a hand-edited backup carries an `items` array and one of
  those Items collides with an existing Item ID. The rest still import.

Only `.json` files are accepted, and a file that is not a valid backup is rejected before
anything is written.
