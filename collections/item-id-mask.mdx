When a Collection mints ID-based Links, the *mask* is what turns an Item ID into a Link address.
It is three parts — an optional prefix, a digit count, and an optional suffix — and the editor
appears inline the moment you select **Create an ID-based link** in **Settings → Link generation**.

The editor shows a live preview of the address it will produce, so you can see the result before
saving: `qrtub.com/CRA####TL`.

## A reserved numbered pattern

Setting a digit count between 1 and 15 turns the mask into a **reserved numbered pattern**:
prefix, exactly that many digits, suffix. `CRA` + 4 + `TL` produces the template `CRA####TL`,
which an Item ID must match exactly — `CRA0042TL` passes, `CRA42TL` and `CRA0042` do not. The
prefix and suffix can each be up to 20 letters, numbers, hyphens or underscores.

This is enforced, not suggested:

- The item form shows the prefix and suffix as fixed text either side of the Item ID box, so you
  type only the number. Pasting the full value (`CRA0042TL`) works too.
- The format is checked **on the server** on both create and edit, so CSV imports and API calls
  are held to it too, not just the form.
- Matching is case-insensitive, and the affixes are stored exactly as you type them.

**Saving a numbered mask reserves that pattern for your team.** It then appears in the numbered
patterns your team owns, and its number pool is shared. Changing a Collection's pattern later
reserves another one; the pattern it had stays reserved to your team and still counts toward your
plan.

The digit count is required. A blank count used to make a *free-form* mask that wrapped whatever
Item ID you typed; that shape is retired. A Collection that still had one now shows **Don't create
a link** and mints nothing until you give it a numbered pattern. Links it minted before keep
working.

## Adopting a pattern the team already has

If your team has reserved numbered patterns already, the editor lists them under **Use an
existing numbered link**, each with its next number, so a second Collection can join an existing
scheme instead of inventing a parallel one. Pick one and the prefix, digits and suffix fill
themselves in; **— Create a new one —** starts a fresh pattern.

Once the mask matches a pattern the team owns, the editor shows its usage: the next number, the
total generated, how many are currently active, which numbers are used, and the gaps — numbers
below the next one that no Link holds. Deleting an Item does not open a gap: its Link stays in
your unassigned pool and keeps its number.

For what a numbered pattern is in its own right, and how claiming a range works outside a
Collection, see [Numbered Links](/links/numbered-links).

## Conflict rules

**A numbered pattern is deliberately shareable.** Several Collections on the same team can adopt
the same pattern, because they draw from one pool with shared used-number tracking, and each Item
takes an unused number. Adopting a pattern is never blocked by another Collection.

**A pattern reserved by a different team is refused.** Numbered patterns are globally unique, so
if another team holds `CRA####TL` — or any pattern that could produce the same addresses — you
will be asked for different affixes or a different digit count.

**A new pattern counts toward your plan.** Reserving a pattern your team does not hold yet uses
one of the numbered patterns your plan includes, and the editor warns you when your team is near
or at that limit. If your plan includes none and your team holds none, **Create an ID-based link** shows
an upgrade panel instead of the editor, and the settings will not save with it selected.

## Failure modes worth knowing

- **A number whose Link belongs to another Item** cannot be used. The item form refuses it
  before saving ("…is already taken — pick another number"); a CSV import creates the Item
  without a Link and says why in its report. Pick an unused number — the gaps list shows which
  are free.
- **An unattached Link at that address is adopted**, not duplicated, when the Item comes in
  through a CSV import, or when you change an existing Item's Item ID to that number. This is how
  a numbered Tag produced in advance gets picked up. The item form does not do this when you
  *create* an Item: it treats any number that already has a Link as taken.
- **A blank Item ID mints no Link.** The item form and CSV import both require one in this mode,
  but paths that can leave it blank — duplicating an Item that has none, for instance — produce
  an Item with no Link rather than an error.
