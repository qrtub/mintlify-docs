QRtub has two roles: **Owner** and **Editor**. Everyone you invite joins as an Editor. There is no
third role, and no way to change a member's role.

## There is no read-only role

You cannot give someone view-only access. Every member you invite can create Collections and
Items, edit any Item's fields, create and edit Links, build and change Pages, and run print
batches. If a person should not be able to change your data, do not add them to the team.

The word "viewer" appears nowhere in the product, and an Editor cannot be restricted to a single
Collection either — team membership is all-or-nothing across everything the team owns.

## What the owner can do that an Editor cannot

Permissions key off one thing: whether you are **the team's owner**, the single person recorded as
owning the team. That is the only distinction the system actually enforces:

| Action | Owner | Editor |
|--------|-------|--------|
| Edit team name, slug, logo | Yes | No |
| Invite members, resend or revoke invitations | Yes | No |
| Remove members | Yes | No |
| See the team's Subscription section | Yes | No |
| Delete a Collection, or delete an Item | Yes | No |
| Everything else — Collections, Items, fields, Links, Pages, Batches, CSV import and export | Yes | Yes |

Deleting a **Link** is not owner-only — any member can delete or release Links, including ones
somebody else created. Neither is deleting a Draft Batch.

**An Editor cannot delete Items or Collections, and the app does not say why.** Deleting Items gets
the error *Those items no longer exist.* (or *That item no longer exists.* for one), and nothing is
deleted: despite the wording, the Items are still there. Deleting a whole Collection fails quietly:
the confirmation goes through with no error, but the Collection is still there when the list
reloads. If a member reports either, this is why: they are not the owner. Ask the owner to do it.

## How ownership changes

The owner is the one person recorded as owning the team. An invitation cannot make anyone the owner:
the invite form offers no role, and the server refuses any role but Editor with *Members can be
invited as Editor only. To make someone the owner, transfer ownership.*

The team's owner changes in exactly one place: when the current owner leaves the team, which hands
ownership to another member as part of leaving. There is no separate transfer-ownership screen. See
[Leaving a Team](/team/leave-a-team).

Some older memberships may still show **Owner** in the members table's **Access** column, from when
the invite form offered it. That label grants none of the powers in the table above — the person
still sees the Team page as a non-owner, with no Edit button, no invite card and no Subscription
section. Their row has no **X** either; to remove them, tick their row and use **Remove Selected**.
